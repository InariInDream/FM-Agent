  违规汇总（all_bugs 模式，共 2 处）:
    - kind = resource
      触发语句:
        Line 18:         buf = pool.acquire()
        Line 24:                     cache[task["id"]] = buf
      原因: fast 路径把 acquire 来的 buf 直接写入 cache，全程没有容量检查或淘汰逻辑，也不再 release。反例：连续到达 65 个 prio 为 fast 且 id 互不相同的任务，cache 条目数就会增长到 65，超过 MAX_CACHE=64，缓冲区随运行时间无界累积。
    - kind = ordering
      触发语句:
        Line 27:             with lock_b:
        Line 28:                 with lock_a:
      原因: slow 路径（else 分支）先获取 lock_b 再获取 lock_a，顺序与约定相反。反例：任务 prio 不是 fast 时执行到 Line 27-28，先持有 lock_b 再等 lock_a；若此时另一线程按 fast 路径先持有 lock_a 再等 lock_b，两线程互等形成 ABBA 死锁。
